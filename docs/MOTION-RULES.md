# 动画 / 视频制作规则（视频任务自动生效）

> 这份文件是**硬规则**，不是灵感库。任何视频、动画、动效、片头、宣传片任务，读 `VIDEO-KICKOFF.md` 的同时必须读这一份。
> 规则来自 2026-11 的 `apple-ab/` **十版对照实验**（A 幻灯片 → B 分镜 → C 单向一镜 → D 会回头的一镜 → E 全屏扫掠被否 → F 单件动作 → G 运镜抢戏 → H 呼吸镜头 → I 走廊 → J 配乐拍点），每条后面都有实测依据，完整数据见 **[MOTION-CASES.md](MOTION-CASES.md)**。

## 0. 五条铁律（先看这五条）

| # | 铁律 | 违反的样子 |
|---|---|---|
| 1 | **默认一镜到底：不 cut。** 除非用户明确给了场景数和编排 | 一页一页翻，或一个信息点一切 |
| 2 | **元素的出现要有交代**：它为什么此刻出现在这里（被镜头带进来、被别的动作带出来、被送进来、自己长出来都行）。**形式不限**——位移、剪影揭开、slam、甚至淡入都可以 | 凭空出现：上一帧没有、下一帧就在画面正中，观众不知道它从哪来 |
| 3 | **元素的消失也要有交代**，最常见的是镜头移开带走它。**形式同样不限**，但**不许靠切镜头让它不见** | 切走了就等于没了；元素只出现不消失，画面越堆越满，最后只能靠换场景清场 |
| 4 | **场景数没定就先问一句**：几个场景、怎么编排、靠什么衔接。用户没给 → 默认 1 场（一镜到底），并说明理由 | 自作主张做 4 页 / 9 个镜头，最后变成 PPT |
| 5 | **变化必须以「一件东西」为范围**：一次只动一件，工具尺度与被操作物匹配，各件各有自己的时间与方向。**绝不许整幅画面在同一瞬间一起变**（扫光 / 全屏擦除 / 整屏淡入淡出都是换页的伪装） | 一根条子横扫全画面，扫过就没了——那就是转场 |

铁律 1 与铁律 4 是一对：**一镜到底是默认值，不是唯一解**。以后确实需要多场景时，场景数与编排必须先由用户确认或我提出方案被认可。

五条铁律讲的都是画面里发生了什么；**观众能不能跟上**，看下面的 §6（运镜可以参与引导，但必须克制）。

铁律 5 是铁律 2/3 的放大器：**出现与消失的「因果」在观众眼里，靠的是「这一下只动了那一件」**；整屏一起变，再合理的解释也读成翻页。

铁律 2 与铁律 3 说的**不是形式，是因果**。淡入本身没有问题，问题在于「淡入一个观众不知道从哪来的东西」；
滑入也没有天然优势，滑错方向一样出戏。判断一句话：**这一下出现/消失，观众能不能在自己的想象里给它找到原因。**
之前几版之所以难看，不是因为用了淡入，而是因为**元素的消失全部交给了场景切换**——一旦改成不切换，退场就必须真的被拍出来。

## 1. 为什么这样规定（实测依据）

> 十版对照的完整数据、每版为什么被否、踩过的坑，都在 **[MOTION-CASES.md](MOTION-CASES.md)**。规则看不懂时去那里找证据。


**外部参照（冰tree_ 两条片，30fps / 1280×720，实测）**

| | 𝐿𝑖𝑓𝑒（145s，复杂） | 𝑆𝑚𝑖𝑙𝑒（115s，简单） | 我们该学的 |
|---|---|---|---|
| 硬切 | ≈4 次 | ≈6 次 | 都是**长镜**：一条镜头 8–70 秒 |
| 平均镜长 | 31.4s（8.7–69.8） | 15.1s（7.9–17.9） | 别 1–2 秒一换 |
| 全画面动能量 均值 | 3.77 | 3.20 | 一直在动，但**幅度小、连续** |
| 逐秒基线 | 2–3.5 | ≈2 | 不是"忽快忽慢"，是"匀速在走" |
| 字幕 | 贴底固定 | 贴底固定 | 字幕是**屏幕层** |
| 参照系 | 线条网格 / 圆环 / 地平线 | 灭点 + 地平线 | 全片有一个**不动的锚** |

两条片的共同点：**镜头几乎一直在动，但方向从不乱变**（𝑆𝑚𝑖𝑙𝑒 是恒定速度沿路推进，𝐿𝑖𝑓𝑒 是慢速漂移），
观众的眼睛可以锁住灭点或网格——所以画面再动也不晕。反过来，一秒钟往左、下一秒往右的横移，
即使每段都"很稳"，合起来仍然是无参照的乱动。


`apple-ab/` 四个版本，同文案、同色板、同字体、同渲染器、同 15s / 24fps / 无音轨：

| 指标 | A 版面向 | B 分镜 | C 单向一镜 | D 会回头的一镜 |
|---|---|---|---|---|
| 镜头数 | 4 | 9 | 1 | 1 |
| 摄像机运动时间 | 0% | 97% | 100% | 100% |
| 构图中心率 | 100% | 33% | 34% | 43% |
| 文字面积 峰值 | **5.4%** | 18.2% | 15.0% | 17.8% |

三条结论，直接决定上面的铁律：

1. **「文字面积占比」抓不住 PPT。** 最像 PPT 的 A 版文字面积**最低**（5.4%），因为幻灯片是「字少、字大、居中」。别再拿「少放字」当解药。
2. **PPT 感的第一来源是场景切换。** 每切一次，观众都要重新定位一次；一镜到底的版本，观众从头到尾知道自己在哪。这条比任何版式指标都强。
3. **一镜到底 ≠ 一直往前走。** C 版做成了单向推轨 + 结尾拉回，空间像走廊；D 版加入反向与升降，空间才像房间。这不是「必须反向三次」的定额，而是说明：镜头怎么走应当由**观众该看什么**决定，而不是由「我只会往前推」决定。

## 2. 元素入场：常用六种（不是限制清单）

| 方式 | 怎么写 | 适用 |
|---|---|---|
| 顶起 | 从画面下缘或遮挡物后向上移入，`easeBack` 回弹 | 牌子、色块、大块面 |
| 滑入 | 从画外沿运动方向滑进（与镜头同向更自然） | 条幅、标签、小图 |
| 抽出 | 在容器内部用裁剪动画展开（像抽屉 / 过纸） | 文字、色号、数字 |
| 落下 | 从上方落下并停住，像挂上墙 | 窗口、卡片、图版 |
| 抬起 | 从台面抬起 + 轻微旋转 | 剖面、实物板 |
| 伸展 | 长度 / 高度从 0 长出（引线、分割线、进度） | 标注线、连接线 |

这张表是**手感库**，不是白名单。选哪种看「这个东西在这个空间里是怎么被放上去的」：
钉在墙上 → 落下 / 顶起；从抽屉里拿 → 抽出；被推过来 → 滑入；印上去 → 剪影揭开或 slam；本来就摆在那、只是光打上来 → 淡入。

**淡入完全可用**，条件是：① 观众已经知道它在那个位置（前一镜里出现过、或被别的东西指着、或是同一组里的第四张）；② 它淡入时画面别的东西还在动。
缺了这两条，淡入就会读成「幻灯片换页」。

## 3. 进与出：单件动作（物件语法）

元素只出现不消失，画面会越堆越满，最后只能靠切镜头清场——这正是 PPT 的成因。
但"让东西消失"有很多种做法，其中有几种**看着像动作，其实还是换页**。

### 3.1 判据：变化以「一件东西」为范围

| 这一下变化覆盖多大范围 | 观众读到的是 |
|---|---|
| 整幅画面（全屏扫光 / 擦除 / 淡入淡出 / 闪白） | **换了一张**——不管画成线、画成扫、画成擦 |
| 一件东西自己的范围 | **有东西被拿起、推走、盖上、收起** |

所以：**一根与画面同高、横扫过去的墨条 = 转场。** 这是 2026-11 真实犯过的错，别重复。

### 3.2 把内容变成「实物」

每一块内容先问一句：**它在画面里是什么东西？** 牌、纸卡、窗、台纸、板、标签纸……

| 实物 | 进来 | 出去 |
|---|---|---|
| 牌子 | 从某条边界推进，带回弹落定 | 沿同一条边界推走（或对边） |
| 纸卡 | 从边界推进（可带轻微旋转） | 推走 / 被另一张盖住 |
| 卷起的纸 | 从上缘落下 | 落回 | 
| 台纸（大张） | 从下缘升起 | **原路落回**（对称） |
| 窗 / 框 | 从上缘落下 | 向侧边滑出 |
| 标签、引线 | 从边缘抽出 / 伸展 | 缩回 / 随所属实物一起走 |

**原则：进来和出去最好成对**（推进→推走、升起→落回、抽出→缩回）。
成对的进出，观众不需要重新学习这个空间的规则。

### 3.3 工具的尺度必须匹配物件

如果需要"印、刻、擦、刷"这类操作，**工具只做一件东西那么大的范围内的事**：

- ✗ 一根与画面同高的条子扫过整屏
- ✓ 一把卡片高度的刮刀，落到这张卡上，走一趟，抬起来走

工具自己也要有进出（落下 → 走 → 抬起），这样它才是一个"东西"，而不是一层遮罩。

### 3.4 时间就是重量

| 物件 | 典型时长 |
|---|---|
| 大板 / 台纸 | 0.9–1.2s |
| 牌 / 窗 / 纸卡 | 0.6–0.8s |
| 小标签 / 引线 | 0.25–0.4s |

**同类物件不要同时动**：三扇窗错开 0.15–0.2s，三张卡错开 0.1–0.2s。
同时动会读成"一组一起换"，错开才会读成"一件一件放上去"。

### 3.5 退场方式（按"不觉得被耍"排序）

手法不限，从前往后挑；被手拿走、被风吹走、烧掉、化掉都可以，只要在同一个空间里说得通。

| 优先 | 方式 | 什么时候用 |
|---|---|---|
| 1 | **镜头移开**（出画） | 一镜到底时最省事、最自然 |
| 2 | **实物自己走**（推走 / 滑出 / 落回 / 缩回） | 机位不动时的主力；优先用"与进来成对"的方向 |
| 3 | **被另一件盖住** | 替换语义；注意盖住它的那件自己也要有来处 |
| 4 | **被拿走**（手 / 夹子 / 另一件东西带走） | 有具体施动者时最清楚 |
| 5 | **远去**（缩小 + 上移 + 雾化） | 归档 / 退到背景 |
| 6 | **淡出** | 可有，但要有理由；**不可用来清场换内容** |

**唯一禁止**：靠 cut 让东西消失；整屏清空；用白闪 / 黑场掩盖「该拍的退场没拍」；
**用一根扫过全屏的东西把画面一起抹掉**。

### 3.6 做方案时强制自问

> ① 每件东西**怎么进来的**？② 每件东西**怎么出去的**？③ 这一下变化覆盖的是**一件东西**，还是**整幅画面**？

三问有一个答不上来，就等于还没设计完。

## 4. 场景数：必问，且要给建议

用户提到做视频但**没说场景**时，先问这一组（合并成一句，不要分多轮）：

> 「这支片我按 **1 个场景（一镜到底，不 cut）** 做，画面里的东西靠镜头移动与位移进出。
> 如果你要多个场景，告诉我**几个**、每场**各承担什么**、**怎么衔接**（用动作/遮挡接，还是允许硬切）。」

同时给档位建议，帮用户判断：

| 场景数 | 什么时候合适 | 代价 |
|---|---|---|
| **1（默认）** | 单一主体、单一空间、15–60s、产品/概念/风格片 | 需要设计连续空间与运镜路径，制作成本最高 |
| 2–3 | 有明显段落（如"问题 → 方案"、"外观 → 内部 → 场景"） | 每一处切换都要一个"理由"（遮挡、甩镜、推入黑场再出来） |
| 4–6 | 多章节讲解、多产品并列 | 已经接近 PPT，需要每场都有独立镜头语言 |
| >6 | 基本等于幻灯片 | **必须提醒用户**：这会更像 PPT，建议改成一条连续路径穿过所有内容 |

**判断标准不是"几个场景"，而是"每一次切换有没有理由"。** 没有理由的切换就是 PPT。

## 5. 运镜：唯一标准是「视线始终在重点上」

**运镜没有格式要求**——推、拉、摇、移、升降、绕、跟、停，都没有对不对，只有「这一下观众在看什么」。

判据只有一个：**任意时刻，画面里最该被看见的东西，是不是观众的视线所在。**

具体做法就是每半秒问一次：

1. 这一刻的**重点**是什么？（一件东西，不是三件）
2. 观众的眼睛会落在哪？（靠对比度、面积、运动、朝向、唯一在动的东西来引导）
3. 两者一致吗？不一致 —— 要么动镜头，要么改画面，要么把不足重点的东西压下去（缩小、降对比、移出色域）。

一次只引导一件事。观众同时被两个东西抓住，就等于没抓住任何一个。

常见失衡与修法（**工具箱，不是规范**）：

| 症状 | 修法 |
|---|---|
| 重点不在画面中间，观众先看到边上的大色块 | 把大色块移出画，或把镜头推近到重点 |
| 一堆东西同时在动 | 只留一个在动，其余先停住 |
| 观众盯着刚出现的东西，忘了上一句 | 让新东西出现在旧重点的延长线上，视线不用重找 |
| 内容太满，眼睛没落点 | 拉远给空白，或让一个元素占 40% 以上面积 |
| 镜头一直匀速走，看着累 | 到重点前放慢（不是停），离开时加速 |

至于「怎么让空间像房间而不是走廊」——那是**表达需要**，不是规矩：把东西分在不同高度上、偶尔回头、结尾拉全景，都是**可选**手段。用得着就用，用不着不必凑配额；但如果全片只有一条直线匀速前进，观众很难产生「身处其中」的感觉，这一点值得自己多看一眼。

**唯一必须保住的结构**：全片一台摄像机 `{x, y, zoom, rot}`。否则「一个空间」这个前提就不成立了。

### 5.1 运镜与物件怎么分工（G 版实测）

切换其实干了两件事：**把观众带到别处** + **让旧内容消失、新内容出现**。
前者运镜就能做，后者物件自己的进退就能做。两件都做了，就不用 cut。

分工一句话：**镜头负责「看到哪」，物件负责「在不在」。**

三条配套要求：

1. **镜头到之前，东西必须已经就位**；镜头走了之后，东西才退场。顺序反了就会露出"它凭什么出现"。
2. **退场的方向不能横穿别人已占的位置。** 向右撤的卡片会从右边的窗上压过去，那一下非常假；改成向下撤（离开墙面）就成立了。
3. **工具要带被操作物的原点。** 刮刀、笔、印版如果按绝对坐标画，会飘到物件外面。

### 空间规划模板

```
站点表：  导轨(过渡) → 名字墙 → 色块站 → 多视图墙 → 剖视台(墙下) → 落版
每站：    世界坐标 / 内容 / 入场方式 / 退场方式 / 摄影机到位时的 zoom 与 rot
过渡：    站与站之间留 400–600 单位空纸；空纸是速度感的来源
```

## 6. 读者视角（谁在动，眼睛跟谁）

**一条人眼事实**：一个物体在动，眼睛能做平滑追视（smooth pursuit），不累；
整个画面在动，眼睛没法追，只能拿前庭硬顶——久了就晕、就散、就抓不住重点。

### 6.1 分工

**运镜会改变观众看哪儿。** 它能帮忙，也能坏事——所以不是禁掉，是给它上限。

| | 该干什么 | 不该干什么 |
|---|---|---|
| **元素** | 承担主要引导：新的东西从边缘进来、停在视线舒服处；旧的自己离开 | 一起乱动、互相打架 |
| **运镜** | 可以推近、平移、后撤来"把重点送到画面中心"；**只在换重点的那一拍移动**，移动中匀速、单向、无抖动 | 一路横移推拉替观众走路；一秒左一秒右；为动而动 |

四条上限（超了就砍）：

1. **速度**：位移 ≤ 350 px/s（1920 宽），缩放 ≤ 3%/s。人眼能平滑追视的上限远高于此，但我们不需要用满。
2. **一次一个方向**：改变方向的次数 ≤ 幕数。方向一变，观众要重新定位。
3. **只在切换重点时动**：重点没变就别动；动了就要落在拍子上（见 §6.5）。
4. **动完必须停稳**：每次移动至少要留 1 拍的静止，让眼睛落下来。

判断标准还是那一句：**看完这 15 秒，观众记住的是画面里的东西，还是镜头怎么动。**
记住东西 = 对了；记住镜头 = 过头了。

### 6.2 多件同时动，是可以的

不要理解成"一次只能动一件"。判据不是数量，是**读不读得成一个整体**：

**读得成（可以同时动）**
- 有共同参照：地平线、灭点、字幕轨、角标、画面边距里至少有一个不动
- 同向 / 同节奏：同一套缓动、同一个运动来源（比如"整块板被推走，板上的字跟着走"）
- 有主次：一件是主运动，其余是它的附属（影子、拖尾、被它带起来的碎屑）
- 分深度：不同层的元素按视差同向移动，读成"同一个空间在动"

**读不成（会乱）**
- 方向互相打架（一件向左、一件向右、镜头又在推）
- 速度不一致（一件急停、一件还在匀速）
- 都挤在画面中心抢注意力
- 没有共同参照——所有东西都在动

### 6.3 参照系是底线

**镜头动得越多，画面里越要有一个不动的东西。** 地平线 / 灭点 / 边距 / 角标 / 字幕轨，至少留一个。
参考片 𝐿𝑖𝑓𝑒 靠网格与圆环，𝑆𝑚𝑖𝑙𝑒 靠灭点与地平线；两条片都贴底固定字幕。

### 6.4 屏幕层与世界层（带字幕时的硬要求）

| | 属哪层 | 谁在动 |
|---|---|---|
| 字幕条、角标、进度 | 屏幕层（screen space） | 不动，只在换句时换内容 |
| 画面里的物体，以及**物体上的字** | 世界层（world space） | 跟着物件一起进出、一起缩放 |

**镜头推拉时，绝不能让字幕跟着缩放。** 一旦两层混了，观众立刻觉得"这画面是假的"。
推论：**镜头越爱动，越不能把字画在世界层里**；反过来，字要跟着物体动，镜头就得克制。

### 6.5 运动频率由音乐决定（没音乐时只过体检）

配乐一旦定了，元素与运镜的加速、停顿、切点都该跟着拍子走——**音乐的频率就是画面的频率**。
没有配乐时不必强求节奏，只要通过下面这套体检即可。

### 6.6 体检（`_templates/viewer_audit.py`）

```bash
python _templates/viewer_audit.py "<项目>/out.mp4" --band 996,1046
```

| 指标 | 怎么读 | 及格线 |
|---|---|---|
| 全画面动能量 均值 | 所有像素的平均变化 | < 3.0（参考片 3.2–3.8；我们自己的 H 是 1.7） |
| 边缘动能量 均值 | 外圈 12px（只有墙/背景）≈ 镜头在动 | < 1.0 |
| 字幕带 静止段 | 字幕该完全不动 | < 0.8 |
| 高动能量段 | 每一段都要能说出「是哪一件在动」 | 说不出来就是乱 |

## 7. 节奏

- 剪辑点尽量落在拍网格上（120 BPM → 0.5s；90 BPM → 0.667s）。
- 镜长（有剪切时）1.5–4.5s；一镜到底不看镜长，看**方向变化次数**与**行程**。
- 元素入场时刻不要挤在一起：至少间隔 0.15–0.3s，观众眼睛跟得上。

## 8. 验收（出片前逐条打勾）

- [ ] 切换次数 = 0（或 = 用户确认的场景数 − 1）
- [ ] 每一次切换都写得出理由（遮挡 / 甩镜 / 推入）
- [ ] 每个元素的**出现**都有交代（形式不限，但观众能给它找到原因）
- [ ] 每个元素的**消失**都有交代（镜头移开 / 收起 / 被遮挡 / 淡出……皆可），**没有任何元素靠 cut 消失**
- [ ] **没有任何一次性变化覆盖整幅画面**（扫光 / 全屏擦 / 整屏淡入淡出都算换页）
- [ ] 每件实物都有**成对的进出**（推进→推走、升起→落回、抽出→缩回）
- [ ] 同类物件**错开**出场，没有"一组一起换"
- [ ] 淡出没有被用来清场换内容（淡出可以有，但不能替掉「切场景」）
- [ ] **逐段问过「这一刻观众在看什么」**：每个重点都能指出，且镜头/画面确实把它交到了观众眼前
- [ ] `movingTime` 不必强求 100%，但**画面不该长时间完全静止**；静止段要问一句「这里为什么不看点什么」
- [ ] 构图中心率 ≤ 40%；文字面积峰值 ≤ 22%（次要指标，不作判据）
- [ ] 收尾时观众知道「刚才看完的是一个整体」，而不是「最后一张图看完了」
- [ ] 场景数与编排已由用户确认，或我已提出方案并说明理由

命令（lemo 路线）：

```bash
node _templates/metrics.mjs "<项目目录>" 0.25     # 文字面积 / 构图中心率 / 行程 / 运动时间
node core/render/still.mjs "<项目目录>" 0.6 2.6 5.6 8.4 11.4 14.9 --out "<项目目录>/stills"
node core/render/video.mjs "<项目目录>" --fps 24 --out "<项目目录>/out.mp4"
```

## 9. 反面教材（都发生过）

| 现象 | 根因 | 修法 |
|---|---|---|
| 四页翻页感 | 每页一个信息点 + 元素淡入 | 改成一镜到底，元素靠位移进出 |
| 九镜但每镜都像封面 | 每镜独立构图、无空间关系 | 单一空间 + 镜头走位；每镜都留着上一站的边角 |
| 单向推轨，像滑轨视频 | 摄像机只往一个方向走 | 加后撤、倒退、升降、反向摇 |
| 元素只出现不消失 | 退场全部交给了场景切换，改成不切换后就没人管了 | 方案阶段就逐个写退场；优先「镜头移开」 |
| 越做越像 PPT | 场景数没确认，默认做成了多页 | 先问场景数；>4 场主动预警 |
| 文字面积达标但仍像 PPT | 拿错了指标 | 看构图中心率、运动时间、切换次数 |

## 10. 一页速查

```
默认：1 个场景，不 cut，一台摄像机。
出现：形式不限，但要有交代（顶起 / 滑入 / 抽出 / 落下 / 抬起 / 伸展 / 淡入 都行）。
消失：形式不限，但必须拍出来（镜头移开最省事）；不许靠 cut 让它不见。
物件：每件东西是实物，进出成对；工具只做一件东西那么大的事；同类错开，一件一件来。
铁律：一次只变一件；整幅画面一起变的，就是换页。
运镜：没有格式要求。每半秒问一次「观众现在看什么」，让答案永远是那一个重点。
场景：没定先问「几个 / 怎么排 / 怎么接」；>4 场预警。
读者：视线的主体是元素，运镜只维持动态；多件同时动可以，但要同向/同节奏/有参照。
层：字幕角标在屏幕层，物体和物体上的字在世界层；镜头推拉时字幕不许缩放。
体检：viewer_audit.py —— 全画面 < 3.0、边缘 < 1.0、字幕带静止 < 0.8。
节奏：有配乐就跟着拍子，没配乐只过读者视角。
验收：切换数、出现与消失的交代、视线是否始终在重点上、读者体检。
```
